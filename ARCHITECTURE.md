## 1. Что это и с чего начать чтение

unissh — терминальный менеджер VPS для macOS и Linux. Основной сценарий: открыл → выбрал сервер
стрелками → Enter → ты внутри. Второй по важности — добавление свежего VPS с автоматической
первоначальной настройкой (bootstrap) от root.

**Маршрут изучения кода** (примерно час, если читать подряд):

| Шаг | Файл | Что понять |
|---|---|---|
| 1 | `main.go`, `internal/app/app.go` | точка входа, CLI-диспетчер |
| 2 | `internal/app/config.go` | модель данных: `Server`, `Settings`, `Store` |
| 3 | `internal/app/menu.go` | главный цикл: TUI отдаёт `menuItem`, здесь он исполняется |
| 4 | `internal/app/tui2.go` + `tui2_rows.go` | главный экран целиком |
| 5 | `internal/app/panel.go` | как рисуется панель в рамке и как ловится клик |
| 6 | `internal/app/page.go` | полноэкранные страницы результата |
| 7 | `internal/app/remote.go` | SSH-клиент, TOFU, ProxyJump |
| 8 | `internal/app/connect.go` + `login.go` + `connectwin.go` | интерактивное подключение |
| 9 | `internal/app/bootstrap.go` | самая опасная часть — читать последней и внимательно |
| 10 | `internal/core/` | чистая логика, полностью покрытая тестами |

## 2. Общая картина

Один Go-модуль, два пакета и тонкий `main.go`:

```
main.go                 # 10 строк: version через ldflags → app.Run(version)
internal/app/           # TUI, SSH, работа с ОС. Всё, что «грязное».
internal/core/          # чистая логика: парсинг, форматирование, валидация.
                        # Ни одной зависимости от TUI, i18n, файловой системы*, сети.
```

\* кроме `ExpandPath`, которому нужен `os.UserHomeDir()`.

Разделение сделано ради **гейта покрытия**. Тестировать TUI и SSH до 90% — дорого и хрупко.
Тестировать чистые функции до 99% — дёшево и полезно. Поэтому `scripts/coverage.sh`
меряет покрытие только `internal/core` и валит сборку, если оно ниже `COVER_MIN` (90).
`internal/app` проверяется зелёными тестами и `-race`, но не метрикой.

### Поток управления

```
main()
 └─ app.Run(version)
     ├─ loadStore()                  читаем ~/.config/unissh/servers.json
     ├─ setLang(), applyTheme()      i18n и палитра — глобальные, меняются на лету
     └─ mainMenu(st)                 ← бесконечный цикл
         │
         ├─ runPanelsTUI(st)  ──────► tea.Program (alt-screen)
         │                            рисует 4 панели, ловит клавиши и мышь
         │                            ↓ пользователь выбрал действие
         │                            возвращает *menuItem{action, server|servers}
         │                            и ЗАВЕРШАЕТСЯ
         │
         └─ dispatchMenu(st, res)    switch по res.action:
                                     мастера (askInput/askSelect — свои tea.Program),
                                     страницы результата (page.go),
                                     внешние процессы (ssh, scp)
                                     ↓
                                     возврат в цикл → снова runPanelsTUI
```

`defer tunnels.StopAll()` в `mainMenu` гасит фоновые туннели при выходе — они живут
ровно столько, сколько живёт приложение.

## 3. Главное архитектурное ограничение: один `tea.Program` на терминал

Это то, из чего вырастает вся остальная структура, поэтому объясняю подробно.

`bubbletea` при запуске переводит терминал в «сырой» режим (raw mode), захватывает
`os.Stdin` и начинает эксклюзивно рендерить кадры. **Два `tea.Program` одновременно на
одном tty работать не могут**: они дерутся за ввод, а их рендереры затирают кадры друг друга.
На практике это выглядит как мигающая каша.

Отсюда три следствия, каждое из которых видно в коде.

### Следствие 1: панель не может сама открыть диалог

Когда пользователь жмёт Enter на «Удалить сервер», нужен вопрос «точно?». Но вопрос — это
`askConfirm`, а это ещё один `tea.Program`. Изнутри работающей панели его запустить нельзя.

Решение: панель **записывает намерение и завершается**.

```go
// tui2.go
func (m *panelsModel) openAction(action string) (tea.Model, tea.Cmd) {
    if s := m.curServer(); s != nil {
        m.result = &menuItem{action: action, server: s}
        return m, tea.Quit          // ← выходим из программы
    }
    return m, nil
}
```

`runPanelsTUI` возвращает `m.result`, `menu.go` разбирает его в `dispatchMenu` и запускает
диалоги уже на свободном терминале. После — цикл создаёт панель заново.

Побочный эффект, который оказался полезным: пересоздание модели естественным образом
**сбрасывает мультивыбор**. Удалённые сервера не могут остаться «отмеченными призраками».

### Следствие 2: то, что должно быть без мигания, живёт внутри модели

Создание/переименование/удаление папки через выход-и-возврат мигало бы экраном на каждое
нажатие. Поэтому эти диалоги реализованы как **инлайновые оверлеи внутри самой панели**:
`tui2_prompt.go`, тип `folderPrompt`. Пока `m.prompt != nil`, `handleKey` отдаёт все клавиши
в `handlePromptKey`, а `render` дорисовывает поверх рамку с полем ввода.

Та же логика у режима перемещения сервера (`m.moving != nil`, `tui2_rows.go`):
схваченный сервер едет по папкам за курсором, Enter кладёт, Esc возвращает на место.

### Следствие 3: результаты действий — тоже полноэкранные программы

Изначально `actionHealth`, `actionInfo`, вывод команд и все «✓ готово» печатались обычным
`fmt.Println` **после** выхода из alt-screen. Большое окно схлопывалось, и результат оказывался
куском текста в обычном терминале. Это чинил `page.go` — см. [раздел 11](#11-полноэкранные-страницы-pagego).

## 4. Библиотеки: что взяли и что не взяли

### Взяли

| Библиотека | Зачем |
|---|---|
| `charmbracelet/bubbletea` | Elm-архитектура для TUI: `Init/Update/View`, сообщения, `tea.Cmd` для асинхронщины. Мы используем `WithAltScreen()` и `WithMouseCellMotion()` |
| `charmbracelet/lipgloss` | стили, рамки, выравнивание. Критично: `lipgloss.Width()` считает **колонки терминала**, а не байты |
| `charmbracelet/lipgloss/table` | таблицы (`unissh list`, здоровье парка, журнал) |
| `charmbracelet/bubbles/textinput` | поле ввода с курсором и маской пароля |
| `golang.org/x/crypto/ssh` | программный SSH-клиент: bootstrap, сбор метрик, выполнение команд |
| `golang.org/x/crypto/ssh/agent` | аутентификация через `SSH_AUTH_SOCK` |
| `golang.org/x/crypto/ssh/knownhosts` | разбор и запись `known_hosts` для TOFU |
| `golang.org/x/term` | `IsTerminal()` — чтобы `unissh list` работал в пайпе |

### Сознательно не взяли

**`charmbracelet/huh`** — форм-билдер от тех же авторов. Начинали с него, потом выпилили
полностью. Причины: его формы визуально не сочетались с главным экраном (другие рамки,
другая навигация, нет мыши), а поверх работающей панели их всё равно не запустить.
Мы написали свои `select.go` / `input.go` / `multiselect.go` в едином стиле с `panelBox`.
Последними от huh оставались `huh.Option` (структура из двух полей) и `huh/spinner`;
первое заменено на собственный `selOption`, второй — на `runSpinner` из `page.go`.
Итог: минус две прямые и пять транзитивных зависимостей.

**`sshpass`** — утилита для подстановки пароля в ssh. Не в базовой поставке macOS,
и её авторы сами пишут, что это дыра. Вместо неё — `expect` (штатный на macOS),
пароль передаётся через переменную окружения. См. [раздел 8](#8-ssh-интерактивная-сессия).

**cgo + Security.framework** для Keychain. Тянет за собой кросс-компиляцию с C-тулчейном
и ломает `go install`. Вместо этого — CLI `security`, у которого есть [известное
ограничение](#6-секреты).

**`pkg/sftp`** для передачи файлов. Системный `scp` уже умеет всё, что нам нужно, и —
главное — уважает те же `known_hosts`, ключи и `-J` (ProxyJump), что и наш `ssh`.
Реализовывать это второй раз поверх sftp-библиотеки означало бы завести второй набор
правил безопасности, который рано или поздно разъедется с первым.

**Внешний SFTP/SCP для записи файлов при bootstrap.** Там нужно положить пару конфигов
на сервер. Вместо канала sftp — `Remote.WriteFile`, который делает
`cat > path && chmod mode path` и подаёт содержимое через **stdin**. Ноль зависимостей,
и содержимое файла не попадает в командную строку.

## 5. Конфиг и хранилище

`~/.config/unissh/servers.json` — `{version, settings, servers[], folders[]}`.

```go
type Server struct {
    ID            string   // 8 hex, стабильный
    Name, Host    string
    Port          int
    User          string
    Key           string   // путь к приватному ключу; пусто = вход по паролю
    Auth          string   // "key" | "password"
    Folder        string   // папка-группа; пусто = корень
    Favorite      bool
    ProxyJump     string   // user@host[:port]
    LastConnected string   // RFC3339
    Tunnels       []Tunnel
}
```

**Почему у сервера есть `ID`, а не просто имя.** По `ID` ключуются записи в Keychain
(`<serverID>/<username>`). Если бы ключом было имя, переименование сервера отвязывало бы
от него все пароли. `ID` генерируется из `crypto/rand` (`core.NewID`).

### Атомарное сохранение

```go
func (st *Store) Save() error {
    if st.readOnly { return errors.New(T.ErrConfigReadOnly) }
    st.backupCurrent()                        // снапшот в backups/ (ротация 20)
    writeFileSync(tmp, data, 0o600)           // write + fsync(файл)
    os.Rename(tmp, st.path)                   // атомарная подмена
    return syncDir(filepath.Dir(st.path))     // fsync(каталог)
}
```

Два `fsync` — не паранойя. Без `fsync` файла «атомарно сохранённый» конфиг после потери
питания мог оказаться пустым: `rename` атомарен относительно других процессов, но не
относительно кэша страниц. Без `fsync` каталога сама запись директории могла не дойти до диска.

### Read-only при битом конфиге

Если `json.Unmarshal` упал, мы **не начинаем с пустого списка**. Копия кладётся в
`servers.json.broken`, `st.readOnly = true`, и любая попытка `Save()` возвращает ошибку.

Причина проста: раньше при битом JSON стор поднимался пустым, и первое же действие
пользователя (например, «избранное») вызывало `MustSave()` и стирало все сервера.
Снимается флаг только успешным восстановлением из бэкапа (`backup.go`).

## 6. Секреты

Системная ключница через CLI (не через cgo), сервис `unissh`, аккаунт
`<serverID>/<username>`. Passphrase от ключа — под аккаунтом `passphrase/<путь к ключу>`.

| ОС | Хранилище |
|---|---|
| macOS | Keychain через `security` |
| Linux | Secret Service через `secret-tool` (GNOME Keyring, KWallet) |
| ничего из этого | `~/.config/unissh/secrets.json`, права 0600 |

Файл — не «запасной вариант на всякий случай», а честный последний рубеж: на
headless-сервере демона ключницы нет, и записывать пароль больше некуда. Поэтому
`secretGet` всегда проверяет и ключницу, и файл: пароли могли лечь в файл до того,
как в системе появилась ключница.

### Известное ограничение, которое стоит понимать

```go
exec.Command("security", "add-generic-password", "-U", "-s", appName,
    "-a", secretAccount(serverID, username), "-w", secret)
```

Пароль здесь **в argv** и на доли секунды виден в `ps` локальному пользователю.
У CLI `security` нет неинтерактивного способа подать секрет через stdin. Для
однопользовательского Mac это приемлемо; альтернатива — cgo + Security.framework.
Записано в ограничениях сознательно, а не забыто.

Забавно, что на Linux этой проблемы нет: `secret-tool store` читает секрет из **stdin**.
Тот редкий случай, когда линуксовый CLI аккуратнее макосного.

### Автоочистка буфера обмена

Когда пароль кладётся в буфер, мы заводим фоновую задачу на его стирание —
но **сам пароль в argv этой задачи не попадает**:

```go
// clipboard.go, clipCopyEphemeral
sum := sha256(secret)
sh -c 'sleep 45; if [ "$(<paste> | <hash> | cut …)" = "<sum>" ]; then <clear>; fi'
```

В командной строке живёт только хеш. Сравнение по хешу нужно, чтобы не затереть буфер,
если пользователь за эти 45 секунд скопировал туда что-то своё.

Сами команды подставляются по платформе (`core.ClipClearScript` только склеивает):

| Окружение | copy | paste | clear |
|---|---|---|---|
| macOS | `pbcopy` | `pbpaste` | `printf "" \| pbcopy` |
| Wayland | `wl-copy` | `wl-paste --no-newline` | `wl-copy --clear` |
| X11 | `xclip -selection clipboard` | то же `-o` | `printf "" \| xclip …` |
| X11 (запасной) | `xsel --clipboard --input` | `--output` | `--clear` |

Две ловушки. `wl-paste` без `--no-newline` дописывает `\n`, хеш не сходится, и буфер
не чистится никогда. И под Wayland `xclip` работает через Xwayland, не видя буфер нативных
приложений, — поэтому при заданном `$WAYLAND_DISPLAY` мы предпочитаем `wl-clipboard`,
даже если `xclip` установлен.

## 7. SSH: программный клиент

`remote.go`. Используется там, где нужен машинный вывод: bootstrap, сбор метрик,
выполнение команд, дашборд здоровья.

### Порядок методов аутентификации

`dialSSH` собирает `[]ssh.AuthMethod` строго в этом порядке:

1. **приватный ключ** (`keyAuthMethod`). Если ключ под passphrase — пробуем фразу из
   Keychain; если её нет, возвращаем `(nil, nil)`, а не ошибку — пусть попробует агент;
2. **ssh-agent** (`SSH_AUTH_SOCK`);
3. **пароль** — сразу двумя методами: `ssh.Password` и `ssh.KeyboardInteractive`.

Третий пункт неочевиден. Многие sshd (особенно с PAM) отключают `password` и оставляют
`keyboard-interactive`, который для пользователя выглядит так же. Без второго метода
подключение к таким серверам падало бы с «no supported methods remain» при правильном пароле.

### TOFU: доверие при первом подключении

```go
func tofuHostKeyCallback() (ssh.HostKeyCallback, error) {
    base, _ := knownhosts.New(knownHostsPath())
    return func(hostname string, remote net.Addr, key ssh.PublicKey) error {
        err := base(hostname, remote, key)
        if err == nil { return nil }

        var ke *knownhosts.KeyError
        if errors.As(err, &ke) && len(ke.Want) == 0 {
            // хост незнаком → дописываем отпечаток
            ...
            return nil
        }
        return &hostKeyChangedError{inner: err}   // отпечаток ИЗМЕНИЛСЯ → отказ
    }, nil
}
```

Ключевая деталь — `len(ke.Want) == 0`. `knownhosts.KeyError` возвращается в двух разных
ситуациях: «хоста нет в файле» (`Want` пуст) и «хост есть, но ключ другой» (`Want` заполнен).
Первое — норма при первом подключении. Второе — потенциальный MITM, и мы обязаны отказать.
Дописывание идёт под `knownHostsMu`: дашборд здоровья ходит на все серверы параллельно.

`known_hosts` намеренно **один и тот же файл** для программного клиента и для системного
`ssh` (`-o UserKnownHostsFile=...`). Иначе у пользователя было бы два независимых
представления о доверии, и «Сбросить отпечаток» чинило бы только одно из них.

### ProxyJump

`x/crypto/ssh` не умеет `-J` из коробки. `dialViaJump` делает это руками:
подключается к бастиону, открывает через него TCP-канал до цели (`jClient.Dial`),
и поднимает поверх этого канала второе SSH-соединение (`ssh.NewClientConn`).
Оба клиента закрываются вместе (`Remote.Close`).

### Выполнение команд

```go
full := "LANG=C LC_ALL=C sh -c " + shellQuote(cmd)
```

Локаль прибита гвоздями: весь парсинг вывода (`free`, `df`, `/proc/stat`, `os-release`)
рассчитан на английский. Без этого на сервере с русской локалью `df` печатал бы
«Использовано» и всё разъезжалось.

`Run` возвращает `(код, вывод, ошибка транспорта)` и различает три исхода: успех,
ненулевой код (`ssh.ExitError` → это **не** ошибка транспорта) и таймаут.
`Sh` — обёртка, которая превращает ненулевой код в ошибку с хвостом вывода.

`lineWriter` копит вывод и отдаёт **целые строки** в колбэк — так спиннер bootstrap
показывает последнюю строку `apt upgrade`, не подавившись частичным чанком.

### Инвариант: `sanitizeRemote`

**Любой вывод сервера перед печатью в локальный терминал проходит через `sanitizeRemote()`.**
Она срезает ANSI и управляющие последовательности. Причина: удалённая машина может быть
скомпрометирована, а escape-последовательности умеют переставлять курсор, менять заголовок
окна и в некоторых терминалах — подставлять текст во ввод.

Этот инвариант нарушался трижды (монитор, спиннер шага, хвост ошибки в `Sh`) — каждый раз
это чинилось точечно. Сейчас `sanitizeRemote` стоит в `Sh`, в `statsSampleCmd`,
в `stepSpinner.setLine`, в `runResultLines`, в `journalTable` и в `healthStatus`.

## 8. SSH: интерактивная сессия

`connect.go`, `login.go`, `connectwin.go`.

**Почему не `x/crypto/ssh`?** Программный клиент не умеет нормально отдать пользователю
полноценный tty: пробрасывать размер окна, сигналы, `Ctrl+Z`, мышь внутри `htop`, sixel.
Поэтому для интерактива запускается системный `/usr/bin/ssh` — со всеми нашими опциями.

### Общие аргументы

```go
func sshCommonArgs(s *Server) []string   // -o StrictHostKeyChecking=accept-new
                                          // -o UserKnownHostsFile=<наш known_hosts>
                                          // -i <key> -o IdentitiesOnly=yes
                                          // -J <bastion>
func sshArgs(s *Server) []string          // -p <port> + common + keepalive + user@host
func scpArgs(s *Server) []string          // -r -P <port> + common
```

Разделение появилось после рефакторинга: у `ssh` порт — строчная `-p`, у `scp` — **заглавная
`-P`** (строчная `-p` у scp означает «сохранить времена файла»). Это классическая ловушка
при копипасте, поэтому на неё есть отдельный тест `TestScpArgsPortIsCapital`.

### Авто-ввод пароля через expect

Для серверов с парольной аутентификацией пользователь не должен вручную вставлять пароль
из буфера. Мы генерируем Tcl-скрипт и запускаем `expect`.

Два режима, и разница между ними принципиальная:

**Inline (в текущем окне)** — пароль передаётся через `env UNISSH_SSHPASS`:

```tcl
set timeout 30
set pw $env(UNISSH_SSHPASS)
spawn ssh "-p" "22" ... "root@1.2.3.4"
expect {
  -nocase "password:"  { send -- "$pw\r" }
  -nocase "passphrase" { send -- "$pw\r" }
  timeout {}          ;# вход по ключу: приглашения не будет
  eof { exit }
}
interact                ;# отдаём сессию пользователю
catch {wait} result
exit [lindex $result 3] ;# пробрасываем код выхода ssh
```

Пароль не пишется на диск и не виден в `ps` (окружение процесса читает только владелец).

**Новое окно терминала** — env через `open warp://launch/...` не доедет. Поэтому пароль
встраивается в скрипт литералом, файл создаётся с правами 0600 и **удаляет сам себя**
первой же строкой после запуска (`catch {file delete [info script]}`).

Тонкость в блоке `expect`: `send` срабатывает **только по совпадению** с «password:» или
«passphrase». Если пароль неверный, ssh покажет приглашение второй раз — и оно уйдёт
пользователю, а не зациклит скрипт.

Для неинтерактивных программ (`ssh -N` туннеля, `scp`) хвост другой: вместо `interact` —
`set timeout -1; expect eof`. Общий код вынесен в `expectPasswordBlock` и `spawnLine`.

### Новое окно

`connectwin.go` смотрит на `$TERM_PROGRAM`:

- **Warp** не имеет AppleScript-API. Зато читает YAML-конфиги из
  `~/.warp/launch_configurations/` и умеет URI-схему `warp://launch/<имя>`. Пишем конфиг,
  открываем URI. Команда кладётся в literal block scalar (`|`) — не нужно экранировать кавычки.
- **iTerm2** и **Terminal.app** — через `osascript`.
- Fallback — Terminal.app, он есть всегда.

Если окно не открылось, `actionConnect` откатывается на inline-подключение, предварительно
вызвав `cleanup()` — чтобы временный скрипт с паролем не остался на диске.

### Когда фиксируется «последний вход»

```go
if err := openConnectionWindowCmd(s, cmd); err == nil {
    recordConnection(st, s)      // ← только после успеха
```

Раньше `recordConnection` вызывался до попытки, и `last_connected` обновлялся даже у
недоступного сервера. Сортировка по «недавним» врала.

Для inline-режима проверяется код выхода: `255` — это «не удалось подключиться»,
и такая попытка в журнал не идёт (`sshConnErrCode`).

## 9. Главный экран (`tui2.go`)

Четыре панели в стиле lazygit:

```
┌─ СЕРВЕРЫ ────────────┬─ ДЕЙСТВИЯ ──────────┐
│ ▾ prod               │ ❯ [•] Подключиться  │
│     ● web-1          │   [ ] Информация    │
│     ● db-1           │   [ ] Выполнить...  │
│ ▸ staging   3        ├─ СТАТИСТИКА ────────┤
│   ○ old-box          │ Пинг   ● 12 ms      │
├─ МЕНЮ ───────────────┤ CPU    ████░░ 42%   │
│ ❯ [•] Добавить       │ RAM    ███░░░ 31%   │
│   [ ] Здоровье парка │ Туннели ● L :5432   │
└──────────────────────┴─────────────────────┘
 tab — панели · space — отметить · ? — справка
```

### Модель

`panelsModel` держит: стор, карту статусов (`probeResult` по ID), карту живой статистики,
строки списка, курсоры и прокрутку трёх панелей, фильтр, мультивыбор, состояние режима
перемещения и инлайнового промпта, и `regions` — кликабельные прямоугольники.

### Строки списка

`tui2_rows.go` разворачивает дерево «папки → серверы» в плоский `[]listRow`:

```go
type listRow struct {
    kind   rowKind   // rowFolder | rowServer
    folder string
    server *Server
}
```

`rebuildRows()` вызывается после любого изменения: фильтр, сортировка, сворачивание папки,
приход статусов (сортировка по пингу от них зависит). Тонкость: **активный фильтр
принудительно разворачивает все папки** — иначе искомый сервер прятался бы в свёрнутой группе.

Неизвестная папка (например, конфиг правили руками) трактуется как корень — `folderOf()`.

### Панель в рамке и клики мышью

`panel.go`, функция `panelBox(title, items, w, h, focused, cursor, off)`.

Возвращает две вещи: строки бокса и **экранную координату каждого видимого пункта**
(`[]int`, `-1` для скрытых). Из них `render()` собирает `m.regions`, а `handleMouse`
превращает `(x, y)` клика в индекс пункта.

Внутри — два прохода. Первый прикидывает окно прокрутки. Если сверху или снизу что-то не
влезло, надо зарезервировать строки под индикаторы «▲ ещё 3» / «▼ ещё 7» — а это уменьшает
окно, и его нужно пересчитать. Без второго прохода последний элемент молча обрезался.

`shift` в расчёте координат учитывает верхний индикатор: он сдвигает все пункты на строку
вниз, и без поправки клики попадали бы не туда.

### Мультивыбор

`tui2_select.go`. `space` отмечает сервер под курсором; на строке папки — всю группу
(если отмечена частично — добираем остальные, если целиком — снимаем).

Пока `m.selected` непуста, правая-верхняя панель показывает **групповые действия**
(`curActions()` возвращает `batchActions()` вместо `serverActions(s)`), а правая-нижняя —
список отмеченных вместо живой статистики (снимок одного сервера ничего не говорит о группе).

`clampActionCur()` не даёт курсору действий уехать за конец: групповых пунктов меньше,
чем действий сервера.

`selectedServers()` возвращает сервера **в порядке конфига**, а не экрана — чтобы
сортировка списка не меняла порядок выполнения групповой команды.

### Гард минимального размера

Ниже 64×18 панели схлопываются и раскладка ломается. `renderTooSmall` показывает
понятную просьбу растянуть окно вместо мусора.

## 10. Живая статистика

Панель справа-внизу — встроенный монитор. Раз в 2 секунды по тикеру снимается срез метрик
выделенного сервера.

### Почему одно постоянное соединение

Наивная реализация делала бы `openRemote → Run(monCmd) → Close` на каждый тик. Это полный
цикл TCP + обмен ключами + аутентификация каждые две секунды. На сервере с `fail2ban`
это выглядит как перебор и заканчивается баном.

Поэтому `panelsModel` держит **одно живое соединение** на выделенный сервер:

```go
statsRemote   *Remote  // открытое соединение
statsID       string   // к какому серверу оно открыто
statsConnID   string   // к какому серверу ПРЯМО СЕЙЧАС идёт подключение
statsSampling bool     // опрос по открытому соединению уже выполняется
```

`refreshStats()` — конечный автомат с четырьмя защитами:

```go
if s == nil                     → dropStatsConn(); ничего не делаем
if statsID != "" && != s.ID     → dropStatsConn()      // курсор уехал
if !statsVisible() || offline   → return nil            // панель скрыта / сервер мёртв
if statsRemote == nil {
    if statsConnID != ""        → return nil            // подключение уже в процессе
    statsConnID = s.ID; return statsConnectCmd(s)
}
if statsSampling                → return nil            // предыдущий опрос не закончился
statsSampling = true; return statsSampleCmd(...)
```

`onServerChanged()` при смене курсора просто **закрывает** соединение и возвращает `nil`.
Новое откроется на ближайшем тике. Это естественный дебаунс: быстрая прокрутка списка
не порождает шторм подключений.

`serverOffline()` не даёт ходить к мёртвому серверу: каждый `dial` висел бы до таймаута
и тут же начинался заново.

### Дельты

`monCmd` одной командой снимает `/proc/loadavg`, `free -b`, `df -P -k /`, `head -1 /proc/stat`,
`/proc/net/dev`, `nproc`, `uptime -p` и список внешних IP. Секции разделены `\n@\n`.

CPU% и скорость сети — величины **дифференциальные**: из одного снимка их не получить.
Поэтому `liveStat` хранит `prev`, а `core.CPUNetDeltas` считает:

```go
total = Σ(statB[i] - statA[i])   для i < n
idle  = (statB[3] - statA[3]) + (statB[4] - statA[4])   // idle + iowait
cpu   = (total - idle) / total
```

До второго снимка панель показывает `…` вместо CPU — честнее, чем нарисовать 0%.

## 11. Полноэкранные страницы (`page.go`)

Появились последними и починили заметный дефект UX.

**Проблема.** «Здоровье парка» собирало метрики, `runPanelsTUI` уже завершился, alt-screen
восстановил обычный экран — и таблица печаталась `fmt.Println` в терминал. Пользователь
видел, как большое окно схлопывается и вместо него появляется «маленькое», а под ним — его
шелл. То же с информацией о сервере, выводом команд, паролями и всеми «✓ готово».

**Решение.** Четыре примитива, каждый — свой `tea.Program` с `WithAltScreen()`:

| Функция | Что делает |
|---|---|
| `showPage(title, lines)` | прокручиваемая страница в такой же рамке, что и панели. `↑↓ / PgUp / PgDn / g / G` и колесо мыши; `Esc` / `q` / `Enter` — назад |
| `runPage(title, status, lines, load, keys)` | то же, но `load()` выполняется **внутри** страницы под спиннером. Плюс дополнительные клавиши-действия |
| `showToast(msg)` | сообщение по центру, гаснет само через 1.1 с или по любой клавише |
| `runSpinner(status, fn)` | ожидание без результата: спиннер, который закрывается сам, когда `fn` вернулась |

Все четыре — одна модель `pageModel` с флагами `load`/`ttl`/`auto`.

`runSpinner` заменил `huh/spinner` и сохранил его важное свойство:

```go
_, err := tea.NewProgram(m, tea.WithAltScreen()).Run()
<-done   // дожидаемся fn ВСЕГДА, даже если пользователь нажал Ctrl+C
```

Без `<-done` `Ctrl+C` завершал бы программу, оставляя горутину `fn` дописывать результат
в переменные, которые вызыватель уже читает. Это гонка данных, и `-race` её находит.

### Где мы намеренно печатаем в обычный терминал

Три места, и у каждого есть причина:

1. **интерактивный `ssh`** — забирает tty себе, это и есть смысл действия;
2. **`scp`** — рисует свой прогресс-бар, которому нужен настоящий tty;
3. **поток bootstrap** — это последовательный лог на несколько минут; его нужно видеть
   целиком и прокручивать в скроллбэке.

### Остаточное ограничение

Каждая страница — отдельная `tea.Program`, поэтому на переходе между экранами терминал
технически выходит из alt-screen и тут же входит обратно. Контент в скроллбэк больше не
утекает, но теоретически возможно короткое мерцание на стыке. Полностью убрать его можно,
только отрисовывая страницы оверлеем внутри самой панельной модели — что сложно, потому
что `info` и `health` умеют спрашивать пароль.

## 12. Bootstrap: инварианты против потери доступа

`bootstrap.go` — самая опасная часть проекта. Он подключается к свежему VPS от root,
создаёт пользователя, ставит ключ, настраивает файрвол и **отключает вход по паролю**.
Ошибка на любом шаге может оставить пользователя без доступа к серверу, за который он платит.

Порядок шагов в `Run()` спроектирован именно против этого. **Не менять, не поняв, зачем.**

1. **Пользователь и ключ ставятся до любых изменений sshd.**
2. **`verifyUserLogin` — реальный вход по ключу с проверкой членства в admin-группе —
   выполняется до харденинга.** Не работает → харденинг не начинается вовсе.
3. **Файрвол открывает и старый, и новый порт до смены порта.** Плюс `configureSSHD`
   перед сменой порта best-effort открывает новый порт в ufw/firewalld, даже если шаг
   «firewall» не выбирался. Иначе смена порта отрезала бы доступ.
4. **`configureSSHD` — самая тонкая функция:**

   ```
   apply()                              записать конфиг
   sshd -t                              проверить синтаксис  → при ошибке revert()
   [открыть порт, ssh.socket, semanage]
   restart sshd                                              → при ошибке revert()
   verifyUserLogin(новый порт)          реальный вход        → при ошибке revert()
   ```

   `revert()` работает **через живую root-сессию**: TCP-соединение переживает рестарт sshd,
   поэтому даже если новый конфиг сделал вход невозможным, у нас всё ещё есть руки на сервере.
   Ошибка внутри `apply()` тоже вызывает `revert()` — конфиг не остаётся в полусостоянии.

5. **Харденинг пишется в `/etc/ssh/sshd_config.d/00-unissh.conf`.** Префикс `00-` обязателен:
   в sshd выигрывает **первое** прочитанное значение директивы, а cloud-init кладёт свои
   настройки в `50-cloud-init.conf`. Файл `10-...` проиграл бы им.

   Прежнее содержимое drop-in копируется в `/etc/ssh/00-unissh.conf.unissh-prev` — **вне**
   `sshd_config.d/`, иначе бэкап сам попал бы под `Include *.conf` и sshd прочитал бы его
   как конфиг.

6. **Если у системы нет `Include`** — правится основной `sshd_config`:
   - бэкап через `test -e || cp`, а не `cp -n`: на coreutils ≥ 9.2 `cp -n` возвращает
     код 1, когда файл существует, и шаг падал бы на ровном месте;
   - `sed` удаляет прежние директивы **только до первого `Match`-блока**
     (`/^[Mm]atch /,$!{...}`) — внутри `Match` те же директивы означают другое;
   - свои значения вставляются в строку 1.

7. **Ubuntu 22.10+ слушает порт через `ssh.socket`**, а не `ssh.service`. Перед сменой порта
   сокет отключается, служба включается. На RHEL — `semanage port` (best-effort, SELinux).

8. **Пароль пользователя идёт в `chpasswd` через stdin**, не в командной строке. И
   сохраняется в Keychain **сразу** после успешного `chpasswd` (колбэк `onPassword`).
   При аборте на следующем шаге пароль всё равно показывается пользователю
   (`result.Password` возвращается даже при ошибке) — иначе новый пароль был бы утерян,
   а старый в Keychain стал бы нерабочим.

9. **Публичный ключ добавляется в `authorized_keys` через stdin** (`$KEY=$(cat)`), а не
   через `echo '...'`: комментарий в `.pub` может содержать кавычки и сломать shell.

10. **Критические шаги** (юзер, ключ, проверка входа) прерывают настройку.
    **Некритические** (обновление, fail2ban, swap) добавляют предупреждение и продолжают.

Дистрибутивы: Debian/Ubuntu (`apt`, группа `sudo`, ufw) и RHEL-семейство (`dnf`/`yum`,
группа `wheel`, firewalld). Прочие — только пользователь + ключ, с предупреждением.

## 13. Проброс портов

`tunnels.go` + `tunnels_ui.go`. Правила лежат в `Server.Tunnels`, живые процессы — в
`tunnelManager`.

### Флаги

| Вид | Флаг | Смысл |
|---|---|---|
| `local` | `-L lp:rhost:rp` | порт у нас → хост:порт со стороны сервера |
| `remote` | `-R rp:rhost:lp` | порт на сервере → хост:порт с нашей стороны |
| `dynamic` | `-D lp` | SOCKS5-прокси на нашем порту |

Обратите внимание на порядок чисел у `-R`: первым идёт порт **на сервере**. Это второй
источник путаницы после `-P`/`-p`, поэтому на него тоже есть тест.

### Три неочевидных решения

**`ExitOnForwardFailure=yes`.** Без него `ssh -N` при занятом локальном порте поднимается
успешно, печатает предупреждение в stderr и живёт — туннель числится рабочим, но не работает.
С этой опцией ssh падает сразу, и мы показываем причину.

**`Setpgid: true` + убийство группы.** Процесс запускается в собственной группе, чтобы
`Ctrl+C` в терминале не убил туннель в обход менеджера. Гасим сигналом всей группе
(`syscall.Kill(-pid, SIGTERM)`): при парольном входе внутри группы живут `expect` **и** его
дочерний `ssh`. Убей мы только `expect` — `ssh` остался бы сиротой, держащим порт.

**`reap` под мьютексом.** Горутина ждёт `cmd.Wait()`, потом решает, что делать:

```go
if m.procs[key] != p {
    return   // туннель уже заменён новым запуском — чужую ошибку не пишем
}
```

`Stop()` удаляет запись из карты **до** того, как посылает сигнал. Поэтому `reap` видит
подмену и не записывает «упал» для того, что мы погасили руками.

`stderr` читается только после `Wait()` — тот сам дожидается завершения копирования,
так что гонки нет. Текст проходит через `sanitizeRemote`, как и любой вывод сервера.

**Порт-конфликт** проверяется только для `-L` и `-D` (`core.TunnelListensLocally`):
у `-R` порт слушает сервер, локального конфликта быть не может.

## 14. Передача файлов

`transfer.go`. Системный `scp -r`, потому что он уже уважает наши `known_hosts`, ключи и `-J`.

Единственная содержательная логика — экранирование путей, и она в `internal/core/path.go`.

**Удалённый путь** попадает в шелл на той стороне. Значит, пробел и `;` в нём — это
потенциальная команда на сервере. Но просто закавычить всё нельзя: тогда `~/` перестанет
раскрываться и файл уедет в каталог с буквальным именем `~`.

```go
func RemotePathArg(p string) string {
    switch {
    case p == "":               return "."
    case p == "~", p == "~/":   return "~/"
    case strings.HasPrefix(p, "~/"):
        return "~/" + quoteIfNeeded(p[2:])   // тильда голая, хвост экранирован
    }
    return quoteIfNeeded(p)
}
```

`~/'my dumps'` в sh раскрывается правильно — тильда вне кавычек, остальное внутри.

**Локальный путь** разбирает сам `scp`, и он считает всё до первого двоеточия именем хоста.
Путь `weird:name` был бы принят за `weird:` + `name`. Поэтому `LocalPathArg` добавляет
явный префикс `./`.

## 15. Журнал

`journal.go`. JSON Lines в `~/.config/unissh/history.jsonl`, права 0600, ротация на 1 МиБ.

```json
{"at":"2026-07-10T12:00:00Z","kind":"run","server":"web-1","host":"1.2.3.4","cmd":"uptime","code":0}
```

Записываются подключения, команды с кодами выхода и передачи файлов. Все запуски команд
проходят через `runOn()` — единственную точку, поэтому запись одна и её нельзя забыть
добавить в новом месте.

Дописывание идёт под `journalMu`: `runOnTargets` выполняет команду на нескольких серверах
параллельно, и записи не должны перемешаться внутри строки.

Записи старого формата (без поля `kind`) читаются как подключения — `kindOf()`.
Битые строки пропускаются: один испорченный байт не должен прятать весь журнал.

**Безопасность.** В командах могут оказаться секреты (`mysql -pPASSWORD`). Файл 0600,
в просмотрщике есть «Очистить журнал», и об этом честно написано прямо на экране.
Журнал не попадает в бэкапы конфига.

## 16. Здоровье парка

`health.go`. Опрашивает весь парк параллельно (не более 8 SSH-сессий) и показывает
таблицу CPU/RAM/диск/load, отсортированную «самое горячее — наверх».

Два решения:

**TCP-проба перед SSH.** Офлайн-сервер отсеивается за 1.5 секунды, а не держит весь сбор
до SSH-таймаута. Один мёртвый VPS не должен делать дашборд бесполезным.

**`openRemote(s, false)`** — в параллельном сборе пароли не спрашиваются. Иначе восемь
горутин попытались бы открыть восемь форм ввода на одном tty.

CPU считается по дельте двух снимков `monCmd` с паузой 350 мс — тот же механизм, что у
живой статистики, через `computeDeltas`.

Сортировочный вес строки — `worst()`, максимум из четырёх метрик. `loadPerCPU` нормирован
на число ядер: иначе 8-ядерный сервер с load 4.0 выглядел бы хуже одноядерного с load 1.5,
хотя первый загружен наполовину, а второй — в полтора раза.

## 18. Как это тестируется

Задача: покрыть тестами приложение, которое живёт в TUI и ходит по SSH, не имея ни tty,
ни серверов.

### Швы `func` → `var`

Ключевые точки объявлены как переменные, а не функции — тесты их подменяют:

```go
var dialSSH    = func(host string, port int, ...) (*Remote, error) { ... }
var openRemote = func(s *Server, askPassword bool) (*Remote, error) { ... }
var runSelect  = func(title, header string, labels, descs []string, initial int) int { ... }
var runInput   = func(title, def string, password bool, validate func(string) error) (string, bool)
var runMulti   = func(title string, opts []multiOption) ([]string, bool)
var runPage    = func(title, status string, lines []string, load func() []string, keys []pageKey) string
var runToast   = func(lines []string)
var runSpinner = func(status string, fn func() error) error
var tunnelSpawn = func(s *Server, t Tunnel) (*exec.Cmd, func(), error)
var fetchHealth = func(s *Server, timeout time.Duration) healthRow
var scpRun      = func(s *Server, args []string) (int, error)
```

Благодаря `runSelect`/`runInput`/`runMulti` мастера (`addServerFlow`, `actionEdit`,
`settingsMenu`) прогоняются целиком, без терминала.

### In-process SSH-сервер

`sshserver_test.go` поднимает настоящий SSH-сервер на `127.0.0.1` с ed25519 host key и
обработчиком `exec`:

```go
host, port := startTestSSHServer(t, true, func(cmd string) (string, int) {
    if strings.Contains(cmd, "os-release") { return "ID=ubuntu\n", 0 }
    return "", 0
})
```

Это позволяет прогонять `bootstrap` и `remote.go` через **реальный транспорт**:
настоящее рукопожатие, настоящие каналы, настоящий `ExitStatus`.

Внутри стоит `t.Setenv("SSH_AUTH_SOCK", "")` — иначе `dialSSH` подхватывал живой
ssh-agent разработчика и подвисал в согласовании.

### Драйв bubbletea-моделей напрямую

`tea.Program` не нужен: модель — обычная структура.

```go
m := newPanelsModel(demoStore())
var mm tea.Model = m
mm, _ = mm.Update(tea.WindowSizeMsg{Width: 110, Height: 32})
mm, _ = mm.Update(keyMsg("/"))     // включили поиск
mm, _ = mm.Update(keyMsg("w"))
_ = mm.(*panelsModel).View()       // View не должен паниковать
```

### `TestMain`: изоляция

```go
func TestMain(m *testing.M) {
    setLang("en"); applyTheme("blue")     // детерминированный рендер
    os.Setenv("HOME", tmpdir)             // ни один тест не тронет реальный ~/.config
    runPage    = /* no-op, но load() вызывается */
    runToast   = func([]string) {}
    runSpinner = func(_ string, fn func() error) error { return fn() }
    ...
}
```

Подмена `HOME` появилась не сразу: однажды тест затёр реальный конфиг пользователя,
и его пришлось восстанавливать из Keychain.

### Страж i18n

`i18n_test.go` через рефлексию проверяет два инварианта:

1. **ни одного пустого строкового поля** в `trRU` и `trEN`;
2. **совпадение format-плейсхолдеров** между языками — иначе `fmt.Sprintf` напечатает
   `%!d(MISSING)` только у половины пользователей.

Первый инвариант сразу нашёл реальный баг: `HelpFolderOrder` был объявлен в структуре `L`,
но не задан ни в одном словаре — в справке рядом с `shift+↑↓` висела пустая подпись.
Компилятор о таком не сообщает: нулевое значение строки — это пустая строка.

### Гейты

```
make build   →  fmt-check → vet → test → cover-check → go build
make ci      →  test → test-race → vet → cover-check → build
make release →  fmt-check → vet → test → cover-check → goreleaser
```

Собрать или выпустить релиз на красных тестах или с покрытием ядра ниже 90% **невозможно**.

## 19. Хроника проблем и решений

Порядок примерно хронологический. Это самая полезная часть документа: тут видно, какие
ошибки типичны и как они себя проявляют.

### Перенос строк рвал кириллицу пополам

`wrapText` считал длину в **байтах**. В UTF-8 кириллическая буква занимает два байта,
поэтому русский текст переносился примерно на половине доступной ширины.
Лечится `lipgloss.Width()`, который считает колонки терминала (и правильно обрабатывает
эмодзи двойной ширины).

Тот же класс ошибки — обрезка строки. `core.OneLine` режет по рунам, а не по байтам.

### Паника в горутине из-за пустого `/proc/stat`

```go
statFields := strings.Fields(parts[3])[1:]   // ← паника, если parts[3] пуст
```

Если сервер вернул обрезанный вывод, `Fields` даёт пустой слайс, и `[1:]` паникует.
Причём паника происходила внутри `tea.Cmd`-горутины и роняла всё приложение.
Исправлено проверкой `len(statFields) > 1`.

### Реальный out-of-range, найденный `gosec`

`gosec` (правило G602) указал на `core.CPUNetDeltas`:

```go
n := minInt(len(statB), 8)
...
idle += statB[4] - statA[4]   // ← statA короче statB → паника
```

Длина бралась по одному снимку, а индексировались оба. Если сервер вернул разное число
полей в двух замерах (обрезанный вывод, другое ядро), приложение падало.

```go
n := minInt(minInt(len(statA), len(statB)), 8)
```

Это тот случай, когда линтер нашёл не стилистику, а настоящий баг. `gosec` включён,
исключения (G204, G304 и др.) прописаны точечно с обоснованием в `.golangci.yml`.

### Инъекция в `~/.ssh/unissh_config`

`sshConfValue` экранировал кавычки, но пропускал `\n`. Имя сервера с переводом строки
позволило бы дописать в экспортируемый конфиг произвольную директиву — например,
`ProxyCommand`. Теперь `\r` и `\n` заменяются на пробел до всякого квотирования.

### Битый конфиг стирал все сервера

Описано в [разделе 5](#read-only-при-битом-конфиге). `readOnly`-режим.

### Пинг всегда показывал 0

Форматирование округляло длительность до целых миллисекунд. У быстрых серверов
(и у чего угодно в локальной сети) TCP-проба укладывается в доли миллисекунды, поэтому
пользователь видел ровный `0 ms` вместо `0.4 ms`.

```go
func FormatPing(d time.Duration) string {
    ms := float64(d.Microseconds()) / 1000.0
    if ms < 10 { return strconv.FormatFloat(ms, 'f', 1, 64) }  // ← один знак после запятой
    return strconv.FormatFloat(ms, 'f', 0, 64)
}
```

Заодно значок и пинг формирует **одна** функция `statusDotPing` для всех мест сразу,
а статусы различаются не только цветом, но и **формой** (`●` / `✗` / `○`) — для
монохромных терминалов и дальтоников.

### Тест подвисал из-за живого ssh-agent

`TestDialSSHRunSuccess` зависал на машине разработчика, но не в CI. Причина: in-process
SSH-сервер видел `SSH_AUTH_SOCK` и `dialSSH` пытался аутентифицироваться ключами агента,
уходя в долгое согласование. `t.Setenv("SSH_AUTH_SOCK", "")` внутри `startTestSSHServer`.

### `-race` находил EOF при записи файла

`TestRemoteShAndWriteFile` падал под детектором гонок: тестовый сервер закрывал канал,
пока клиент ещё писал stdin. Исправлено на стороне тестового сервера — он читает stdin
в отдельной горутине, потом `CloseWrite()`, `<-drained`, `Close()`.

### Тесты писали в реальный конфиг

`demoStore()` не задавал `path`, и `MustSave()` (вызываемый по клавише `f` — «избранное»)
писал `.tmp` прямо в каталог пакета. Плюс отсутствие подмены `HOME` в части тестов.
Теперь `path` указывает в `os.TempDir()`, а `TestMain` подменяет `HOME` глобально.

### Удаление v1 молча выпилило рабочую фичу

При переходе на панельный дизайн был удалён `toolsMenu` — и вместе с ним единственный путь
к «Выполнить на нескольких серверах». Компилятор промолчал, потому что функция осталась,
просто её никто не вызывал. Нашлось только при ручной проверке.

Мораль: `golangci-lint` с включённым `unused` ловит недостижимый **код**, но не
недостижимую **фичу**. Проверять надо по списку пунктов меню.

### Мёртвая настройка «подтверждать подключение»

После удаления v1 попап подтверждения стал недостижим, и переключатель в настройках
превратился в no-op. Удалены и попап, и настройка, и весь `menuKind`.

### Долгий тест

`TestBootstrapVerifyUserLoginFails` шёл 12 секунд из-за реальных `time.Sleep` между
попытками входа. Задержка вынесена в переменную `verifyLoginRetryDelay`, тест ставит её в 0.

### Экран схлопывался на каждом результате

Описано в [разделе 11](#11-полноэкранные-страницы-pagego). Появился `page.go`.

### `HelpFolderOrder` без перевода

Поле объявили, значение не задали. Найдено тестом-стражем i18n (см. раздел 18).

## 20. Известные ограничения

- **Keychain через argv**: пароль на мгновение виден в `ps` локальному пользователю.
  Приемлемо для однопользовательского Mac; ужесточение потребует cgo.
- **Ключи с passphrase**: поддержаны через ssh-agent и Keychain, но интерактивного запроса
  фразы нет. Зашифрованный ключ без агента и без сохранённой фразы не подключится
  (программный клиент).
- **Live-монитор и bootstrap требуют Linux** на сервере (`/proc`, `apt`/`dnf`, `systemd`).
  BSD не поддержан.
- **Кроссплатформенность — macOS и Linux, без build-тегов.** Всё системо-зависимое ходит
  через три шва: `goos`, `lookPath`, `getenv` (объявлены в `clipboard.go`). Тесты их
  подменяют, поэтому `detectClipTool`, `linuxTerminalArgv` и `detectSecretBackend`
  проверяются под обе ОС с любой машины. `osascript` и Warp остаются macOS-only:
  на Linux новое окно открывается через `$TERMINAL` или белый список эмуляторов, а если
  их нет — `connectInNewWindow()` возвращает false, и мы честно подключаемся inline.
- **Без ключницы на Linux** (headless, залоченный кошелёк) пароли уходят в `secrets.json`
  0600 открытым текстом. Это реальный откат по безопасности, см. SECURITY.md.
- **Туннели живут, пока живёт unissh.** Это осознанный выбор: иначе панель «активных
  туннелей» врала бы про процессы, которых мы не контролируем.
- **`unissh list` работает без tty**; всё остальное требует интерактивный терминал.
- **Мерцание между экранами**: см. конец [раздела 11](#остаточное-ограничение).

## Приложение: конвенции, которые стоит соблюдать

- Все строки интерфейса — только через `T.*` из `i18n.go`, в **обоих** словарях,
  с одинаковыми плейсхолдерами. Комментарии в коде — на русском, перед каждым методом.
- Любой вывод сервера перед печатью — через `sanitizeRemote()`.
- Пользовательские данные в удалённый шелл — только после валидации регекспом
  (`usernameRe`, `tzRe`, `hostnameRe`) либо через stdin, либо через `shellQuote`.
- Результаты действий рисуются через `page.go`, а не `fmt.Println` + `time.Sleep`.
- Таблицы — только через `newTable()`. Общие опции ssh/scp — через `sshCommonArgs()`.
  Пароль сервера — только через `serverPassword()`.
- `Store.MustSave()` после каждой мутации конфига; `maybeRefreshSSHConfig(st)` после
  изменения списка серверов.
- Цвета — только из констант палитры в `theme.go` (они `var`, их меняет `applyTheme`).
